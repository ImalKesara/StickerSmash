How ImageViewer gets its image

In about three minutes, trace one image value from the screen into a reusable component—and see why the component uses braces.

1. The parent sends a named prop

In src/app/(tabs)/index.tsx, placeholderImage is the result of a local asset require. This JSX passes that value under the prop name imageSource:

<ImageViewer imageSource={placeholderImage} />

Think of it as a function call carrying one object: { imageSource: placeholderImage }. JSX uses the braces around placeholderImage to say “evaluate this JavaScript variable”; without them, JSX treats the attribute contents as text.

2. The component receives one props object

React invokes the component with its props object. Your function parameter is { imageSource }, which destructures (extracts) its imageSource property into a local variable of the same name.

type Props = {
  imageSource: ImageSourcePropType
}

export default function ImageViewer({ imageSource }: Props) {
  return <Image source={imageSource} style={styles.image} />
}

The braces inside the parentheses belong to JavaScript object destructuring. The : Props is TypeScript: it says the incoming object must have the shape declared by Props.

3. What the type says

imageSource is the prop's name; ImageSourcePropType is its value type. That type allows the image-source forms React Native defines, including a bundled-file reference returned by require(...) and a remote source object such as { uri: 'https://example.com/photo.jpg' }. The type helps catch invalid values while coding; it does not load or transform the image at runtime.

The component then forwards that local variable as the source prop expected by Expo's Image. So the two names differ on purpose: the reusable wrapper calls its input imageSource; Expo Image calls its input source.

Why not use imageSource directly?

Because this is a React component, React calls it with a single props object—not with each prop as a separate positional function argument. This would be wrong:

function ImageViewer(imageSource: Props) { ... }

Here imageSource would actually hold the whole object { imageSource: placeholderImage }, not the image value. You could write function ImageViewer(props: Props) and use props.imageSource instead. Destructuring is a shorter way to get that same property.

Likewise, at the call site, <ImageViewer imageSource={placeholderImage} /> names the prop. You cannot write <ImageViewer placeholderImage /> because JSX needs a prop name and value, and React components receive those named values in the props object.

Quick check

Without looking back: in function ImageViewer({ imageSource }: Props), what do the braces do? And in imageSource={placeholderImage}, what do those braces do?

Check your answer

Function-parameter braces destructure the props object. JSX braces evaluate a JavaScript expression (the variable's value).

Try changing the local asset passed to ImageViewer, or pass a URL-shaped source object. The wrapper stays the same because both values fit its declared source type.
