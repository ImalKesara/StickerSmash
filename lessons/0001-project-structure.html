Lesson 01 · Expo fundamentals

Find your way around StickerSmash

In two minutes, learn the one folder rule that helps you place most changes correctly.

The mental model

Think of the project as three layers: screens live in src/app/, shared UI and logic live elsewhere under src/, and Expo setup plus dependencies live in root config files.

src/
  app/                 screens and navigation
    _layout.tsx        shared navigation shell
    index.tsx          first screen: route /
assets/images/        image files
app.json              Expo app settings
package.json          dependencies and commands

Follow a screen from startup

  1. package.json says the app starts at expo-router/entry.
  2. Expo Router looks at route files in src/app/.
  3. _layout.tsx wraps screens in a Stack navigator.
  4. index.tsx is the screen at the starting path /.

That is file-based routing: the file tree helps define the app's URLs and navigation. A later src/app/about.tsx would represent /about. Put reusable buttons or helpers in src/components/ or another folder outside src/app/, so Router does not treat them as screens.

Where would a change go?

Want to change the first screen's text? Open src/app/index.tsx. Want a second screen? Add a route file under src/app/. Want to change the app icon or splash screen? Check the paths and settings in app.json. Want an image in the UI? Put it under assets/images/ and reference it from a screen.

Try a quick recall

Without looking above: where would you put (1) a reusable sticker button, (2) the app icon path, and (3) the initial screen? Say the file or folder for each. Then try changing only the home-screen sentence in src/app/index.tsx and run the project to see Fast Refresh update it.

Remember: route screen = src/app/; reusable piece = outside it; Expo identity/settings = app.json.
